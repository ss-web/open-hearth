# Техническое задание

## Цель

Публичный сайт фонда «Открытый очаг»: миссия, правила, очередь, жеребьёвка, казна и отчёты. Посетитель без учётной записи проверяет баланс и пересчитывает жребий. Скрытой операции, которая меняет сумму или порядок, в системе нет.

Учебный режим обязателен, пока нет юридического лица. Сайт прямо говорит, что деньги не принимаются.

## Стек

- Nuxt 3 и Vue 3, TypeScript, страницы в `pages`.
- Стили BEM в `assets/css/main.css`, без утилитарного фреймворка.
- PostgreSQL 16 в `docker-compose.yml`. Сайт читает базу ролью `hearth_public`.
- Docker-образ сайта — `Dockerfile`, сборка Nuxt в `.output`.
- Языки: русский (без префикса), английский (`/en`), армянский (`/hy`). Тексты в `i18n/locales`.
- Жеребьёвка в `shared/lottery.ts` одна и та же на сервере и в браузере.

## SEO

- `useSeoMeta` на каждой странице: title, description, Open Graph, Twitter.
- `useLocaleHead`: `lang`, canonical и hreflang.
- `public/og.svg` как изображение карточки.
- `GET /robots.txt` разрешает обход и указывает sitemap.
- `GET /sitemap.xml` перечисляет страницы на трёх языках, включая отчёты и официальные раунды.
- 404 отдаёт `noindex`.
- На главной — JSON-LD типа NGO. Имя в данных — Open Hearth, с оговоркой учебного режима в видимом тексте.

## API

- `GET /api/snapshot` — весь публичный снимок: казна, заявки, раунды, проверки.
- `GET /api/health` — источник данных и флаг целостности.
- `GET /ledger.csv` — поступления, расходы и выплаты.

Если `DATABASE_URL` пуст или база недоступна, снимок строится из `shared/ledger.ts`. Полоса на сайте называет источник.

## Приватность в запросе

Публичный JSON не содержит имён, адресов, номеров документов и хэшей детей. Хэши лежат в `application_private`. Настройка базы отзывает у `hearth_public` чтение этой таблицы и проверяет отказ.

## Прозрачность расчёта

Победители не хранятся как отдельная истина. Хранятся входные строки, а `buildSnapshot` заново проводит раунды. `npm run verify` проводит их ещё раз из опубликованного входа и сравнивает список, хэш и след.

Будущий раунд без энтропии не публикует победителей. Рядом лежит учебный прогон с пометкой, что это не результат.

## Приём заявок

В этой версии форма пастора и калькулятор семьи ничего не записывают. Настоящий приём — отдельная работа после регистрации: учётная запись пастора, загрузка документов мимо публичной базы, окно возражений, затем перевод заявки в одобренные. Публичная карточка уже показывает, какие поля вообще имеют право появиться.

## Нефункциональные требования

- Суммы — целые доллары. Доли резерва и пула считаются целочисленным делением, чтобы не зависеть от двоичной дроби.
- Жребий не использует `Math.random` и `Math.log`. Случайность — HMAC-SHA256 и выбор без смещения по модулю.
- Сайт читается с клавиатуры, у кнопок и таблиц есть подписи, на узком экране таблица складывается в карточки.
- Шрифты: Literata и Manrope, для армянского — Noto Serif Armenian и Noto Sans Armenian.

## Приёмка

1. `npm run verify` печатает `verify: ok`.
2. `npm run db:setup` после `docker compose up -d` заканчивается без ошибки и подтверждает, что публичная роль не читает `application_private`.
3. Главная, заявка, очередь, финансы, правила, пасторы, код, отчёты и оба раунда открываются на русском, английском и армянском.
4. Несуществующий адрес показывает свою 404.
5. `robots.txt`, `sitemap.xml` и `ledger.csv` отдаются.
6. На странице завершённого раунда пересчёт совпадает с опубликованным списком.
7. Красная полоса говорит, что деньги отправлять нельзя.
